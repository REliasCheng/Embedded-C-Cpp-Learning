# C 指针与内存实践

三个独立的小程序依次对照值传递、地址传递和堆内存的使用。它们不是合并后的单一工程，各自包含 `main()`，应分别构建。`course/` 内源码保留 day05/day09 原样。

## 地址与值

函数参数是值的副本。想让函数改变调用者持有的变量，需要传入地址，并在函数内解引用；想让对象存活在堆上，则要明确申请、失败检查和释放的责任。对嵌入式 C 来说，这些关系比“会写星号”更重要。

## 文件

| 源文件 | 关键路径 | 观察点 |
| --- | --- | --- |
| `08_指针与函数 - 交换两个数（一）.c` | `main → exchange(int, int)` | 交换只发生在形参副本上，调用者的两个数不变 |
| `09_指针与函数 - 交换两个数（二）.c` | `main → exchange(int *, int *)` | 传入 `&num1`、`&num2`，解引用后写回原变量 |
| `02_内存管理 - 堆内存的使用.c` | `malloc → 判空 → 写入/读取 → free` | 申请与释放的基本闭环 |

这三段代码没有公共驱动层，也不存在跨文件调用关系；将它们保留为对照练习，比硬合并成“内存管理库”更忠实。

## 指针操作

值传递版调用 `exchange(num1, num2)`，函数内部 `a` 和 `b` 的交换不改变 `num1`、`num2`。地址传递版调用 `exchange(&num1, &num2)`，`*a = *b` 通过地址写回调用方。堆内存版用 `malloc(4)` 申请空间，判空后写入 200，最后 `free(a)`；这里的固定 4 字节是课程原写法，不应外推成所有平台上 `int` 的大小。

从仓库根目录分别构建：

```powershell
New-Item -ItemType Directory -Path .build -Force | Out-Null
gcc -std=c11 -Wall -Wextra -pedantic 'projects/02_C语言核心能力/指针与地址访问/course/swap/08_指针与函数 - 交换两个数（一）.c' -o .build/value-swap.exe
gcc -std=c11 -Wall -Wextra -pedantic 'projects/02_C语言核心能力/指针与地址访问/course/swap/09_指针与函数 - 交换两个数（二）.c' -o .build/pointer-swap.exe
gcc -std=c11 -Wall -Wextra -pedantic 'projects/02_C语言核心能力/动态内存管理/course/heap/02_内存管理 - 堆内存的使用.c' -o .build/heap-allocation.exe
```

## 内存说明

传值时函数只操作副本；传地址时函数可以修改调用者数据；分配堆内存后，程序还必须负责释放。课程示例集中在这些机制，空指针、分配失败、整数尺寸和复杂生命周期需要在接口中另行处理。
