# C 语言核心能力

## 项目简介

围绕地址访问、资源生命周期、结构化数据和文件 I/O 组织课程原版与个人改进。课程代码的教学边界保留在 `course/`，新增实现只放 `practice/`。

## 技术背景

数据能被修改，不代表访问一定安全；资源能被打开，不代表异常路径会自动关闭。这里重点检查所有权、有效长度和失败返回。

## 软件结构

| [指针与地址访问](指针与地址访问/docs/V1指针与内存专题.md) | 值传递与地址传递交换 | 与动态内存主题分开分析 |

| [文件 I/O](文件IO/docs/改进说明.md) | 结构体数组写入与读回 | [检查 I/O 结果](文件IO/practice/checked_records.c) |

## 核心实现

`int_buffer_create` 先检查输出参数和乘法尺寸，再申请空间；释放函数把调用方指针置空。`checked_records` 检查打开、传输数量和关闭结果，并要求显式提供输出路径。

## 关键代码分析

原堆内存案例的 `malloc(4)` 隐含类型尺寸假设；个人版本改用 `count * sizeof(int)`，并先判断乘法溢出。原文件案例直接搬运结构体内存，个人版本补足错误路径，但仍沿用本机二进制布局；它不是跨平台文件格式。

## 调试记录

课程例子在先前版本中已分别构建。两个个人版本在 GCC 16.1.0 下启用警告即错误后构建、运行通过；文件示例另用不存在的目录验证返回错误码 1，正常路径验证两条记录。

## 嵌入式关联

分配失败、对象布局和资源释放同样影响嵌入式软件；在不提供堆或文件系统的目标平台上，应重新选择接口实现，不能直接移植主机端代码。
