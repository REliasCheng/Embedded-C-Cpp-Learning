# 嵌入式软件思想

## 项目简介

把前四组代码中的接口、状态和资源问题连接到嵌入式设计。这里有一份可运行的**主机端状态机实践**，没有真实板级驱动或硬件测试。

## 技术背景

嵌入式软件通常需要区分应用逻辑、驱动接口和硬件动作；事件驱动逻辑则要明确状态与转换条件。语言练习提供机制，但不是完整设备实现。

## 核心实现

`key_fsm.h` 定义状态、事件与状态机结构；`key_fsm.c` 实现事件转换；`main.c` 用两条事件序列验证短按返回 true、长按释放不触发短按。这是纯逻辑模型，不读取 GPIO。

## 关键代码分析

`KEY_IDLE → KEY_PRESSED → KEY_HELD` 由 `PRESS` 和累计 `TICK` 驱动，`RELEASE` 把状态复位。阈值 3 只是主机端演示常量，不对应已测量的毫秒数或真实消抖参数。

## 调试记录

GCC 16.1.0 以 `-Wall -Wextra -Werror -pedantic` 构建，短按和长按序列断言通过，退出码 0。没有串口、示波器或实物按键结果。

## 嵌入式关联

日后接入硬件时，应由输入驱动产生边沿事件、由稳定定时源产生 `TICK`，并单独验证消抖与阈值。当前先把“状态转换规则”与“读取硬件”分离。
