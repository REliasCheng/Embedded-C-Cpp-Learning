# 从 C 接口到嵌入式软件结构

C 代码进入 MCU 工程后，语法本身通常不是难点。更重要的是数据宽度、缓冲区边界、模块接口和状态变化能否在有限资源下保持清楚。

## 数据宽度与位操作

[定宽整数与位运算](../projects/01_C语言基础能力/README.md)把数值宽度写进类型，并通过掩码读取或修改指定 bit。寄存器、协议字段和状态标志都依赖同样的操作方式；接入具体芯片时，还要以数据手册给出的位宽和读写属性为准。

## 缓冲区必须同时传递长度

[数组求和实践](../projects/01_C语言基础能力/数组与字符串/practice/array_sum.c)把地址与元素数量作为两个参数。命令处理框架沿用这一规则：环形缓冲区保存字节，解析器另外维护容量、当前位置和行结束状态。只传首地址而不传有效长度，调用方无法判断可访问范围。

## 所有权与失败路径

[指针与内存练习](../projects/02_C语言核心能力/README.md)区分值传递、地址传递和堆内存生命周期。嵌入式程序更常使用静态或固定容量缓冲区，但仍要明确谁负责写入、谁读取、失败时返回什么，以及数据何时失效。

## 头文件定义模块边界

[多文件工程与回调](../projects/03_程序设计能力/README.md)把声明、实现和入口分开。调用方只依赖头文件中的类型与函数；模块内部状态留在 `.c` 文件。回调进一步把“何时触发”和“触发后做什么”分开，命令表和任务表都使用这一结构。

## 状态转换可以脱离硬件检查

[主机端状态机](../projects/05_嵌入式软件思想/状态机思想/docs/转换与测试.md)用事件推动状态变化，并通过断言检查转换结果。接入 MCU 时，按键、UART 或定时器负责产生事件，状态机本身仍只处理输入和下一状态。

具体板级工程还需要结合原理图、引脚复用、外设时序和中断资源。对应实现见 [STC89C52RC 工程](https://github.com/REliasCheng/stc89c52-learning)。
