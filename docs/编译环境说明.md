# 编译环境说明

当前公开仓库只包含维护者编写的 `practice/` 源码与主机端测试，不包含历史课程源码。主机验证从仓库根目录执行，输出写入已被 `.gitignore` 排除的 `.build/`。

## 综合软件实践测试

需要 Python 3 和 GCC 或 Clang。统一入口会使用 C11、`-Wall -Wextra -Werror -pedantic` 构建四个独立测试程序，并逐一执行：

```powershell
python scripts/run_host_tests.py --compiler gcc
```

Linux 或已经安装 Clang 的环境可执行：

```bash
python3 scripts/run_host_tests.py --compiler clang
```

Linux CI 还会执行一组轻量 AddressSanitizer / UndefinedBehaviorSanitizer 验证：

```bash
python3 scripts/run_host_tests.py --compiler gcc --sanitizers
```

测试入口使用 `assert`，因此不得定义 `NDEBUG`。Sanitizer 结果只说明本次受测路径没有报告对应问题，不构成通用内存安全保证。

## 其他个人实践

每个示例拥有独立入口，只编译该示例的真实依赖。例如：

```powershell
New-Item -ItemType Directory -Path .build -Force | Out-Null

# C 多文件实践
gcc -std=c11 -Wall -Wextra -Werror -pedantic `
  projects/03_程序设计能力/多文件工程设计/practice/main.c `
  projects/03_程序设计能力/多文件工程设计/practice/counter.c `
  -o .build/counter-practice.exe
./.build/counter-practice.exe

# C++11 封装实践
g++ -std=c++11 -Wall -Wextra -Werror -pedantic `
  projects/04_C++程序设计/封装设计/practice/main.cpp `
  projects/04_C++程序设计/封装设计/practice/student.cpp `
  -o .build/student-practice.exe
./.build/student-practice.exe
```

`checked_records` 需要显式输出文件参数，建议把测试数据放在 `.build/`。Keil、MCU 交叉编译和开发板验证不属于本仓库的当前验证范围。
