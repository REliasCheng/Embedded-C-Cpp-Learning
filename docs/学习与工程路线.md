# 学习与工程路线

本仓库从 day01–day13 的课程实践中按技术主题选取源码。day 编号用于追溯进阶顺序；仓库目录按能力分组，避免成为整套课程资料镜像。

## 1. C 的执行与数据基础

day01 的 [程序入口](../projects/01_C语言基础能力/day01_程序入口与输出/README.md)建立编译、运行、返回值的最小闭环；day02 的 [定宽整数](../projects/01_C语言基础能力/day02_数据类型与可移植性/README.md)把数据宽度写进类型；day03 的 [位运算与分支](../projects/01_C语言基础能力/day03_位运算与分支/README.md)分别处理二进制位和控制路径。这里形成的是读写基本代码、理解表示和选择结构的能力。

## 2. 数据传递、组织与资源

day05 的 [指针与回调](../projects/02_C语言核心能力/day05_指针与回调/README.md)连接 V1 的 [值传递/地址传递对照](../projects/c-pointer-memory/README.md)；day06 的 [数组参数](../projects/02_C语言核心能力/day06_数组与参数/README.md)暴露“只传首地址但未传长度”的接口边界。day07 的 [字符串存储](../projects/02_C语言核心能力/day07_字符串存储/README.md)区分数组内容与指针指向；day08 的 [结构体和枚举](../projects/02_C语言核心能力/day08_结构体与枚举/README.md)把字段组织成数据对象；day09 的 [内存与文件](../projects/02_C语言核心能力/day09_动态内存与文件/README.md)引出申请、释放、打开和关闭的生命周期。

这组代码能说明机制，也能指出原例的边界：固定数组长度、未检查文件操作返回值、原生结构体二进制布局依赖平台。它们是后续个人改进版的具体问题清单，不是已修复功能。

## 3. 从函数到模块

day04 的 [函数接口](../projects/03_程序设计能力/day04_函数与多文件/README.md)展示参数和返回值的四种形式；V1 的 [多文件工程](../projects/c-module-design/README.md)进一步把 `main.c`、`calc.h`、`calc.c` 分开。day05 的回调则让调用者把行为作为参数交给判断函数。三者合起来形成我对“接口签名、实现位置、调用方向”的基础理解。

## 4. C++ 的对象与容器

day10 的 [标准流](../projects/04_C++程序设计/day10_基础语法与流/README.md)建立 C++ 基本语法；day11 的 [`vector` 操作](../projects/04_C++程序设计/day11_容器操作/README.md)涉及访问和删除边界；day12 的 [引用](../projects/04_C++程序设计/day12_引用与别名/README.md)讨论对象别名；day13 的 [构造函数](../projects/04_C++程序设计/day13_类与构造/README.md)与 V1 的 [类头源分离](../projects/cpp-class-object/README.md)连接对象状态和文件结构。现有精选代码并未构成继承/多态或完整 STL 项目。

## 5. 接向嵌入式软件

[嵌入式软件思想](../projects/05_嵌入式软件思想/README.md)把数据宽度、位操作、缓冲区长度、回调和分层接口与未来驱动设计对应起来。当前文件仍是主机端课程实践；进入真实 MCU 项目时还需要目标硬件、资源约束、接口实现和测试记录。

下一阶段优先围绕现有代码做少量个人版本：数组接口增加长度、文件 I/O 处理失败路径、多文件工程清理头文件变量定义。只有对应代码和验证形成后，再把它们列为个人完成的工程改进。
